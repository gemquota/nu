## 19.0 Scope and dependencies

Part 19 specifies the **experiment plane**: how studies are declared, replicated, branched, and compared — with no UI anywhere in the path (§11.13).

Depends on: 11 §11.12 (experiment contract), 11 §11.13 (replication/observation), 11 §11.26 (invariants 6–7, 10); 12 §§12.40 (branching), 12.41 (counterfactual), 12.42 (configuration model), 12.43 (immutable definitions); the runner of [Part 13](13-simulation-kernel-and-tick-semantics.md) §13.16 and lineage observables of [Part 18](18-evolution-and-selection-architecture.md).

## 19.1 The experiment definition is immutable

From §12.43: once a run begins, the definition is frozen. Runtime state may change; specification may not.

```
ExperimentDefinition (frozen at run start)
├── experimentId        — identity of the study
├── hypothesis          — what is being tested
├── seedPolicy          — root seed + derivation rule
├── config              — world/physiology/behaviour parameters (12.42 domains)
├── systems             — declared schedule deltas (e.g. direct selection on/off)
├── observationPolicy   — what to record, at what cadence
└── checkpointPolicy    — cadence + retention
```

Rules:

- **X1 (Definition immutability).** Mutating a definition mid-run is impossible by construction: the runner consumes a frozen object; "changing" the experiment creates a new `experimentId` (12.43).
- **X2 (Domain-separated configuration).** Configuration is grouped by domain (world/genetics/behaviour/ecology/… per §12.42) so a counterfactual varies one domain without touching others.
- **X3 (Everything declares or defaults).** Every parameter the runner consumes comes from the definition; there are no ambient settings.

## 19.2 Replication

N independent replicates differ only in seed (§11.13, Invariant 6):

```
Experiment(seed S) → replicate rᵢ uses seed derive(S, i)
```

Rules:

- **R-1 (Seed derivation is deterministic and documented).** `derive(S, i)` is a pure function; replicate *i* of experiment *E* can be regenerated by anyone with *E* and *S* (Invariant 10 traceability: Experiment → Replicate → Seed → Model Version → Tick Range → Observation).
- **R-2 (Replicate isolation).** Replicate *i* never mutates state belonging to replicate *j* (Invariant 6). Replicates share nothing but the frozen definition.
- **R-3 (Comparison is statistical).** The framework produces per-replicate trajectories + summaries; claims rest on distributions across replicates, never on a single run.

Aggregate observables across replicates:

```
AggregateStatistics
├── per-tick mean / variance of each metric
├── extinction distribution
├── final-metric distributions (population, energy, diversity)
└── replicate-to-replicate concordance
```

## 19.3 Branching and counterfactuals

From §12.40–12.41 — the scientifically decisive capability:

```
        Snapshot(t)
             │
      ┌──────┴──────┐
      ▼             ▼
  Baseline    Intervention (declared diff)
      │             │
      ▼             ▼
 Trajectory A  Trajectory B
```

Rules:

- **B-1 (Branch identity).** A branch inherits world state, RNG state, model version, and provenance from its parent snapshot, and receives a new branch id. It cannot mutate the parent (Test E, §12.47).
- **B-2 (Declared intervention).** A counterfactual differs from its baseline by exactly one declared diff, e.g. `{ domain: "ecology", key: "pulseProbability", value: 0.10 }`. Everything else is byte-identical.
- **B-3 (Provenance chain).** Every branch records `parentId`, `branchPointTick`, and the intervention diff, so trajectory comparison is attributable to the intervention and nothing else.
- **B-4 (Intervention application).** Config-domain diffs apply before the next tick; state-domain diffs (e.g. kill half the population) are applied as a single atomic system invocation at a declared phase, staged through the normal delta machinery (nothing teleports state).

## 19.4 Comparison

Trajectory comparison is a pure function over observation records (Invariant 3 — observation purity):

```
compare(trajectoryA, trajectoryB) →
  per-metric divergence over tick ranges
  distribution shift across replicates
  divergence onset tick (when the intervention's effect becomes measurable)
```

No comparison routine may write state; no analysis may feed back into the simulation.

## 19.5 Kernel integration

| Concern | Component | Writes |
|---|---|---|
| Replication | runner (N worlds, N streams) | nothing shared |
| Branching | restore + intervention + new branch id | fresh world from snapshot |
| Comparison | observation-plane projections | nothing |

Boundary invariants:

- **I19-A (Replicate equivalence).** For fixed *i*, replicate *i* re-runs bit-identically (Invariant 2 at replicate granularity).
- **I19-B (Branch independence, Test E).** Running a branch leaves the parent checkpoint's bytes unchanged; restoring the parent afterward still yields the pre-branch trajectory.
- **I19-C (Single-diff counterfactual).** The serialized definition of a counterfactual differs from its parent's in exactly the declared key.
- **I19-D (Statistical claim safety).** An aggregate claim must reference ≥ 2 replicates or be flagged as a single-run observation.

## 19.6 What Part 19 forbids

- No UI in any step of §11.30's 15-step acceptance experiment.
- No mutable experiment definitions (X1).
- No cross-replicate shared mutable state (R-2).
- No undeclared differences between a counterfactual and its baseline (B-2).
- No analysis that mutates the trajectories it analyzes.
